# The Token Vault

A static webpage for browsing and downloading a personal library of D&D monster tokens ("Token Vault"). It's a plain HTML/CSS/JS site — no framework, no build step required to run it, just a small pipeline to keep the token list in sync with the image folder.

## How it works

- **`images/`** — source token art (PNG/JPEG), gitignored since it's the raw, unoptimized library.
- **`images-optimized/`** — WebP versions of everything in `images/`, generated by the optimize script. This is what the site actually loads from locally.
- **`tokens.js`** — the token list (`name` + `file` for each token), auto-generated from whichever image folder is available. Do not edit by hand.
- **`config.js`** — sets `IMAGE_BASE_URL`, the prefix used to build each token's image URL. Points at a Cloudflare R2 public bucket by default; swap it for `images-optimized/` to serve images locally, or any other public URL/bucket.
- **`index.html`** / **`style.css`** — page shell and the parchment/dungeon styling.
- **`app.js`** — renders the token grid, live search-as-you-type filtering, and pagination (24 tokens per page). Each token card links directly to its image with a `download` attribute so clicking it saves the file.

## Scripts

```bash
npm run optimize   # convert images/*.png|jpg -> images-optimized/*.webp
npm run tokens     # regenerate tokens.js from images-optimized/ (or images/ as a fallback)
npm run build      # runs both, in order
```

Adding or removing a token is just: drop/remove the file in `images/`, then run `npm run build`.

## Running locally

This is a static site — serve the folder with anything that can host static files, e.g.:

```bash
npx serve .
```

Then open the served URL in a browser.

## Deploying

The intended path is GitHub Pages (or any static host) with images served from `images-optimized/`, or from a remote bucket (Cloudflare R2, S3, B2, etc.) by pointing `IMAGE_BASE_URL` in `config.js` at the bucket's public URL.
